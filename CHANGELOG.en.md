# Changelog

[中文](CHANGELOG.md) · English · [Chinese (upstream original)](CHANGELOG.zh.md)

This document records the changes that the ARTEX Chinese edition (this fork) adds on top of the upstream repository. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

The upstream ARTEX project's per-version release history (0.3.x and earlier) and contributor list are preserved verbatim in Chinese in [`CHANGELOG.zh.md`](CHANGELOG.zh.md). As with `README.zh.md`, the original text is kept unchanged so that it stays easy to compare against upstream changes. The detailed content and rationale for each change can be found in the repository's commit history.

## [Unreleased] · Chinese edition changes

### Security (first-run protection, authentication hardening)

- **Blocked remote takeover of the first-run admin account.** An instance without a password accepted `POST /api/auth/init` unauthenticated, so whoever reached the port first could set the admin password and obtain a JWT (privately reported by Dangel). Initialisation now requires the setup token (`setup_token`), which is printed only on the server console at startup, and wrong attempts are rate-limited. Added `ARTEX_SETUP_TOKEN` (a pinned token that is never logged) and `ARTEX_ADMIN_PASSWORD` (8+ characters, initialises directly) for unattended deployments, plus a token field on the `/setup` screen.
- **Default bind address is now 127.0.0.1.** The `artex -addr` default moves from `:8787` to `127.0.0.1:8787`, and `docker-compose.yml` publishes 8787 as `${ARTEX_BIND:-127.0.0.1}`. Deployments reached from other machines must pass `-addr :8787` or set `ARTEX_BIND=0.0.0.0` in `.env`. Starting without a password on a non-loopback address logs a warning. This edition also translated `.env.example`, the compose file and the install/update prompts into Simplified Chinese, and the install script now points at the setup token.
- **Changing the password invalidates every existing token.** The JWT signing key is derived from the password hash, so a change through the UI, `reset-password.sh`, or a direct DB edit ends earlier sessions (users must log in once after upgrading; the change-password response carries a fresh token so the current browser session continues). `reset-password.sh` now says so, and reminds you to review custom tools, MCP, LLM and notification settings as well when recovering a claimed or leaked account.
- **Replaced wildcard CORS with an allowlist.** Instead of `Access-Control-Allow-Origin: *`, headers are only sent for origins in `ARTEX_CORS_ORIGINS` (comma-separated; the default only allows `next dev` from `dev.sh` at `http://localhost:5173`). Also added server-side minimum password length (8) and audit logs for failed initialisation/login attempts (with client address).
- **Ported the authentication hardening from upstream ARTEX 0.3.15.** Password-setting reads now fail closed with 503 instead of reporting `initialized:false` (`authStatus`, `authInit`, `authLogin`, change-password). First-time setup is atomic via `INSERT ... ON CONFLICT DO NOTHING` ([`db.InsertSettingIfAbsent`](db/settings.go)), so the primary-key constraint protects the existing value even when the read check is unreliable. Passwords over 72 bytes are rejected with 400 instead of 500, and a database connection-pool cap (32) reduces the path where a `too many clients` error can masquerade as a read failure. Ported to match upstream commit `a951e4a` (0.3.15), filling in only what the earlier sync round had not covered.

### Docker deployment path restored

- **This edition can now be started with Docker.** The `artex` service in `docker-compose.yml` used to pull the `autumn27/artex` image, but that image disappeared from Docker Hub when the original author closed the repository (a pull now returns `not found`; the `autumn27` namespace only still holds the two `scopesentry` images). The compose file therefore gained a `build:` section and its image name became a local tag (`${ARTEX_IMAGE:-artex-cn:local}`), so **provided `dist/<arch>/artex` is already in place (that is, `./build-image.sh` has been run once)**, a single `docker compose up -d --build` builds this edition's image and starts it; a fresh clone has no such binary and compose fails at `COPY dist/<arch>/artex`. The old "pull the upstream image" path no longer works.
- **The Dockerfile's "run-only" premise is now reflected in both the docs and the scripts.** This Dockerfile does not compile inside the container; it copies a pre-built Linux binary via `COPY dist/<arch>/artex`. That requires ① a frontend static build → ② a `GOOS=linux` cross-compile → ③ `docker build`, and skipping an earlier step fails at the `COPY`. The README gained a "Building the Chinese edition image locally" section covering that order, the `--platform`/`GOARCH` matching caveat, and the fact that `build.sh` writes to a different path (`dist/artex-linux-amd64/`) than the Dockerfile expects (`dist/<arch>/`).
- **`install.sh`'s "all Docker" path and `update.sh`'s Docker path no longer pull a missing image.** Both now rebuild the image from the current source (`docker compose up -d --build`), and stop with guidance if a required tool (Go, Node.js/npm, rsync) is missing. The now-unused `ARTEX_TAG` prompt was removed from `update.sh`. If the build or the start fails they now print an actionable hint (use "② local compile and run", or the self-built image section of the README) instead of only the raw error.
- **`.env.example` matches the actual behaviour.** `ARTEX_TAG` (an upstream image tag) was replaced by `ARTEX_IMAGE` (the locally built image's tag), and the file now states that compose builds locally and never pulls a pre-published image.
- **The startup failure caused by changing the password later is now documented.** The official PostgreSQL image reads `POSTGRES_PASSWORD` **only once, when the volume is empty**, and uses it for `initdb`; so if you change the password in `.env` after bringing the stack up once, that value is ignored and only artex tries the new password, hitting a `28P01` authentication failure and falling into an abnormal-exit (`code=1`) restart loop (Docker still holds the port, but with no listening process in the container the browser just sees a failed connection). The README (zh/en) gained a "When the page will not open (Docker)" section covering how to check the logs and two recovery paths (`down -v` then re-initialize, or `ALTER USER` to align the password while keeping the volume's data), and `.env.example` carries the same warning. The order is always **`.env` first → `docker compose up -d --build`**.

### Release and CI

- **Image publishing now uses this repository's own namespace.** The docker job in `release.yml` funnels the publishing namespace into `env.IMAGE_NAMESPACE`, whose default is now `ghcr.io/dami9527/artex-cn` (this repository's own GHCR namespace), and logs in with the workflow's built-in `GITHUB_TOKEN` (job permission `packages: write`); the `docker-gate` job that only recognised Docker Hub secrets is gone. After the first publish, check in the GitHub package settings that the package is public — if it is private, `docker compose pull` fails with an authentication error.
- **A guard aborts before the build when the publishing namespace has not been changed.** The docker job's first step fails early when the namespace is empty or is still an upstream/other-fork placeholder (`autumn27/artex`, `jiwoochris/artex-ko`, `ghcr.io/jiwoochris/artex-ko`) and prints an actionable fix; otherwise `docker/login` succeeds and only the final push fails late and confusingly with `denied`.
- **The checksum glob is terminated with `--`.** `sha256sum -- *.zip` removes the risk of a file name starting with `-` being read as an option, and clears the workflow's last actionlint/shellcheck SC2035 finding.
- **Added a cloud build script that does not use Docker (`build-cloud.sh`).** Aimed at cloud build environments that only have Go/Node: install frontend dependencies → `npm run build:static` → copy `web/out` into `server/webui/dist` → compile the single binary with the `embedui` tag, with no Docker involved.

### Frontend fixes

- **Added SSE-disconnect fallback polling to the main-agent console.** The main agent console in the task detail view used to refresh its live transcript only from the SSE stream, so behind a reverse proxy that buffers `text/event-stream`, or when the connection drops, a question and its answer were invisible until a manual refresh. While `sseLive` is false the view now re-fetches the newest page of the active session every 2 seconds and merges it (the same shape as the chat console's always-on polling); it does nothing while SSE is healthy, so the healthy path carries no extra load, and it tracks the maximum `seq` per session so that with no new content it skips the store write and the re-render too.

### UI and output language (Simplified Chinese era)

- **Agent display names seeded by the server now follow the runtime language too.** The agent picker on the chat page shows names that are **not frontend strings but DB seed data** — the `reporter` and `retester` names/descriptions are written into the database as literals at seed time (guarded to run once by `reporter_agent_seed_v1` / `finding_retester_seed_v1`), and the web UI's locale is baked into the HTML at static-export time, so the server cannot see it.
  - A runtime setting `ARTEX_LOCALE` was introduced so the seed labels follow it, and `./build-image.sh` passes the build-time value into the container automatically, so UI and server cannot drift (setting it once in `.env` also works). This repository only ever takes `zh`, and unset or unsupported values fall back to `zh`; later versions resolve the seed language from the runtime display language (the settings table) instead, with `ARTEX_LOCALE` kept as the build script's entry point.
  - For **already-installed instances**, `localizeSeedAgentNames` was added. It rewrites a name only when the current value is one of that agent's **known historical defaults** — i.e. only when **the user has not edited it** — and preserves user-edited names. It is idempotent via the `seed_agent_names_locale` flag, and **re-applies when the flag matches but the actual state does not**.
  - Two defects were caught during implementation: ① the "already at target, skip" check compared against the *target* value, so when the target happened to equal another entry's default the following entry was skipped entirely; ② that bug set the flag without actually renaming, so later boots treated it as done and never fixed it. Both are gone now (**historical-default set matching + state re-verification**), and both are pinned by a DB-backed integration test (`TestLocalizeSeedAgentNames`; four subcases — aligning a historical description to the current Chinese label, preserving a user-edited name and description, re-aligning when the flag is already at the current locale but the state does not match, and changing nothing when flag and state agree) — a class that constant-only unit tests cannot catch. The seeded names follow Chinese only (`ARTEX_LOCALE` always resolves to `zh`), so the test only asserts that the final name and description are Chinese and contain no Hangul.
- **Strings that were still English are now Chinese.** Two gaps, found from a user report.
  - **The sidebar "Preferences" panel** (`web/src/app/(main)/_components/sidebar/layout-controls.tsx`): this was the one file that never used `next-intl`, so its title, description, 8 labels, 12 toggles and `aria-label`s were all hardcoded English (theme preset, fonts, theme mode, page layout, navbar behavior, sidebar style, sidebar collapse mode, restore defaults). A new `layoutControls` namespace now covers all of them via `t()`. The theme presets' `label` values in `theme.ts` are English identifiers, so the stored values are untouched and only the display names are mapped; font names (Geist, Roboto, …) are proper nouns and are not translated.
  - **The 404 page**: the exported `404.html` was Next's built-in English page (`Page not found.`). There were two causes — ① App Router's `not-found.tsx` only creates the internal route for `notFound()`; it is not used for the top-level 404 of a static export (Next 16 needs `global-not-found.tsx` plus `experimental.globalNotFound`). ② `zh.json`'s three `notFound` keys still held **English values** (missed when the Chinese originals were carried over). This adds `global-not-found.tsx` (which must return a full HTML document) plus its body component, and fills in `zh.json`'s `notFound` and `search.empty` with Chinese. Because that page does not inherit the root layout, it passes messages to `NextIntlClientProvider` explicitly (without them, a static export cannot resolve the strings and falls back to the English page again).
- **`scripts/check-no-korean.py` turns "no Korean may remain" into an executable gate.** Values left in a non-Chinese language, like the ones in ② above, cannot be caught by hand and would leak silently. The script scans the text files under the working tree (skipping `.git`, dependency directories such as `node_modules`, build output and binaries), matches Hangul line by line, and exits non-zero with the file, line number and matched content on any hit. It reads source rather than build output, so it is independent of the build language.
- **`build-image.sh` drives the whole build in one command.** The earlier docs and scripts only went as far as making the build paths pass `NEXT_PUBLIC_LOCALE`; they missed that **prefixing `docker compose up -d --build` with that variable does not change the UI.** This project's `Dockerfile` does not compile the frontend inside the container (it does `COPY dist/<arch>/artex`, a pre-built binary with `web/out` embedded), so compose finishes that copy as `CACHED`. The UI is decided when **`next build` runs on the host**. `build-image.sh` performs ① frontend → ② sync into the embed directory → ③ `GOOS=linux` compile → ④ `docker compose up -d --build`, and records the last build in `dist/<arch>/.locale` so it **only rebuilds when the recorded value changed** (reuses otherwise; `--force` to override, `--no-up` to skip starting).
- **`install.sh` and `update.sh` now delegate their build logic to `build-image.sh`.** Keeping two copies of that logic lets the build inputs drift silently (which is exactly what happened), so it lives in one place and the two scripts just call it.
- **The UI locale is chosen with `NEXT_PUBLIC_LOCALE`.** `web/src/i18n/config.ts` already had `LOCALES`, `DEFAULT_LOCALE` and `resolveLocale()`, but **nothing in the build path ever passed `NEXT_PUBLIC_LOCALE`**, so a Chinese UI was impossible (it always fell back to the default). The locale is baked into the HTML at static-export time, which is why it is a build-time choice rather than a runtime switch. This repository first pinned the UI to Simplified Chinese (`LOCALES = ["zh"]`, `DEFAULT_LOCALE = "zh"`), then extended it to the `zh` default with English/Spanish switching described in the section above.
- **The scope and skip rules of `scripts/check-no-korean.py`.** It only looks for Hangul — Hangul syllables, Jamo, compatibility Jamo and the extended-B block — and not for Han characters or kana: Chinese copy is all Han characters, so checking Han would be self-defeating, and kana is Japanese and outside the cleanup target. It skips version-control and dependency directories (`.git`, `node_modules`, `.next`, `out`, `dist`), build output (`server/webui/dist`, `web/out`) and binary files (anything that does not decode as UTF-8). Files needing an exemption go in the script's ignore list, which is currently empty: nothing in the repository should need one.
- **The docs state that the on-screen text and the agent output are separate concerns.** The language of the agent's vulnerability reports, fact summaries, final summaries and chat replies is controlled by Go code (`langDirective()` in `agent/prompt.go`) and is independent of the build-time `NEXT_PUBLIC_LOCALE` value. Changing it means editing `langDirective()` and `agent/prompt_test.go`, which pins its contract.

### UI and output language (Chinese, English, Spanish)

- **The UI and backend output language now default to Simplified Chinese with English/Spanish switching.** The "Display language" setting switches the web UI strings (`web/messages/{zh,en,es}.json`), the reports, summaries and chat replies the agent writes, and server error messages and status labels together. The agent's behavioural-instruction body (the reasoning "brain") is still left in its original language to preserve its benchmarked performance, as are commands, payloads, code and raw logs.
- **The server's default output language comes from `ARTEX_LANG` (or `language` in `config.json`).** Values are `en`/`zh`/`es` (no Korean), with `zh` as the empty-value default. It is the bootstrap default used until a user picks a language, which then takes precedence; operator console logs follow only this value, regardless of the Settings choice.
- **`web/src/i18n/config.ts`'s `LOCALES` grew from `["zh"]` to `["zh","en","es"]`, while `DEFAULT_LOCALE` stays `zh`.** The message catalog expanded from a single `zh.json` into three. `NEXT_PUBLIC_LOCALE` only decides the language of the pre-rendered first page at build time; the runtime value is whatever the user picks. The README (zh/en), `.env.example`, `config.example.json` and `docker-compose.yml` all document these variables.

### Upstream sync (v0.3.15)

Three upstream commits made after this fork's branch point (upstream `d003372`, 2026-10-03) have been brought into this repository. All three landed after that point, so merge conflicts were confined to files the localization had already touched; those spots were resolved to this edition's conventions as described below.

- **Model-fallback approvals now meter their token usage separately** ([`db/llm_usage.go`](db/llm_usage.go), `server/intercept.go`). Approval calls previously had no independent accounting, so there was no way to tell what they cost. They are now metered under `worker=judge`, and a usage card (call count, input, output, cache read, cache write, plus a 30-day daily bar chart) sits under the "Model fallback approval" switch in System → Intercept. Upstream hardcoded this card's strings in Chinese; this repository added `interceptPage.judgeUsage.*` keys to `web/messages/zh.json` so the card goes through the same i18n path as the rest of the UI.
- **The auth-initialization fail-open path is closed** (upstream `a951e4a`; `server/auth.go`, `db/settings.go`). Treating a failed password read as "not configured" let an unauthenticated request overwrite an already-set admin password. Failed reads now return 503, first-time-only semantics rest on the primary-key constraint (`INSERT ... ON CONFLICT DO NOTHING`) instead of an upsert, and password-length validation (at least 8 characters, bcrypt's 72-byte ceiling) is enforced server-side. This edition translated the new error strings and validation messages into Simplified Chinese, and added the setup screen's "cannot confirm" state strings as `auth.setup.*` keys.
- **Upstream `v0.3.15`'s change history is reflected in [`CHANGELOG.zh.md`](CHANGELOG.zh.md).** Upstream's release commit does not fit this repository's split changelog layout, so instead of cherry-picking it verbatim, the entries that sat under `[Unreleased]` were rolled into a `## [0.3.15] - 2026-10-07` section with the original Chinese text preserved.
- **Second sync round (upstream `205ad92` → `1881c2a`, 17 commits).** This round brought in: the first-run setup protection and the second port of upstream 0.3.15's auth hardening (see "Security"), the Chinese/English/Spanish switching with the `ARTEX_LANG` server default (see "UI and output language"), the SSE-disconnect fallback polling in the main-agent console (see "Frontend fixes"), the Docker-free cloud build script `build-cloud.sh`, the release namespace guard and the checksum glob fix (see "Release and CI"), the defense-guide inline Sigma template consistency gate on the detection side, the note in `detections/suricata/README.md` that sid 1000003 is grounded in the pinned upstream dependency `norma/0.4`, and the Windows build-artifact rules in `.gitignore`. Upstream's Korean release notes from this round were not copied: this repository rewrote them as the Chinese entries above, and does not reuse the upstream Korean edition's release suffix.

### Localization (i18n)

- **Pinned user-facing output to Simplified Chinese.** The benchmarked agent's behavioral-instruction body (the "brain") is left in its original language to preserve performance, and a code-level fixed segment (`langDirective`) instructs the agent to write only the user-facing output (vulnerability reports, fact summaries, final summaries, chat replies) in Simplified Chinese. Commands, payloads, code, and raw logs are kept in their original form.
- **Brought the web UI into Simplified Chinese.** Introduced `next-intl` into the Next App Router and put the strings in `web/messages/zh.json`. Screen strings for the dashboard, vulnerabilities, chat, notification delivery, interception, LLM settings, and more are Simplified Chinese.
- **Brought the server API's user-facing errors and responses into Simplified Chinese.** HTTP error and response text that is returned to the browser is Simplified Chinese. Text that feeds back into the agent brain as input, however, was kept in its original language to prevent benchmark drift, and the reasoning behind each such decision is recorded in the repository's working documents.
- **Reorganized the documentation around Chinese.** `README.md` is the default Simplified-Chinese README, `README.en.md` is the English edition alongside it, and the upstream Chinese original is preserved as `README.zh.md`.

### Defense and detection resources

- **Added a defense and detection guide.** A Chinese guide ([`docs/defense-zh.md`](docs/defense-zh.md)) and an English version with the same content ([`docs/defense-en.md`](docs/defense-en.md)) that cover how an autonomous AI attack differs from a traditional scanner, the fingerprints (IoCs) a defender can observe, entry points and hardening, detection rules, and incident response.
- **Provides deployable detection rules.** The guide's fingerprints were turned into rules you can use directly. The host and log layer is covered by [Sigma](https://sigmahq.io) atomic and correlation rules ([`detections/sigma/`](detections/sigma/)), and the network layer by [Suricata](https://suricata.io) rules ([`detections/suricata/`](detections/suricata/)) that target the enrich prober and norma SDK WebFetch User-Agents. The Suricata side also records the one indicator that rests on a pinned upstream dependency: sid 1000003's `norma/` User-Agent is hardcoded in the norma SDK (pinned at `v0.4.3` in `go.mod`) rather than in this repository's source, so the indicator-source test treats it as a pinned dependency.
- **Visualized ATT&CK coverage.** The techniques that the rules tag were organized into a MITRE ATT&CK Navigator layer ([`detections/attack/`](detections/attack/)).
- **Provides machine-readable indicators of compromise (IoCs) in standard formats.** The unique fingerprints that ARTEX emits were collected into a single CSV ([`detections/indicators/artex_indicators.csv`](detections/indicators/artex_indicators.csv)), along with a MISP event ([`detections/indicators/artex_indicators.misp.json`](detections/indicators/artex_indicators.misp.json)) carrying the same indicators that can be imported straight into a threat-intelligence platform. Indicators that a rule backs are marked with `to_ids`, while host-forensic ports are marked separately as triage clues.
- **Attached reproducible detection tests.** Eight test suites prove the rules by actually running them (Sigma structure and compilation checks, Sigma live event-matching, backend portability, SigmaHQ convention lint, Suricata load and firing, ATT&CK layer consistency, indicator-to-source matching, and MISP export ↔ CSV synchronization). A batch runner that runs them all at once plus three non-suite gates (harness-registry sync, the host-triage tool's self-test, and the defense guide's inline Sigma template consistency check) and a pre-commit example were added and wired into the CI merge gate. Sigma live event-matching confirms that the rules not only compile but actually fire on malicious sample events and stay silent on benign ones, for both the atomic and the correlation rules; the inline-template gate re-verifies what the defense guide claims about that Sigma correlation template (it passes `sigma check`, it converts on splunk/eql/loki, lucene/kusto reject the correlation, and the Chinese and English copies carry an identical rule body), so the prose cannot silently go stale when upstream `sigma-cli` moves.

### Repository hardening

- **Added security and misuse warnings and Chinese legal notices.** The scope of use, notices under the Cybersecurity Law, the Data Security Law and the Personal Information Protection Law, and a misuse-prohibition warning were added at the top of the README.
- **Replaced the screen preview with this edition's UI screenshots** ([`screenshots/zh/`](screenshots/zh/)).
- **Set up a maintainer runbook and a contributing guide.** Added a runbook ([`MAINTAINING.en.md`](MAINTAINING.en.md)) for preventing upstream-sync and translation drift, and a detection-rule contribution contract ([`CONTRIBUTING.en.md`](CONTRIBUTING.en.md)). The runbook also documents the release pipeline's build assumptions and how to verify them locally without a tag.
- **Added push/PR merge-gate CI.** The upstream repository ran CI only on tag releases, but this fork runs — on every push and pull request — a Go build, static analysis (`go vet`), and unit tests ([`ci.yml`](.github/workflows/ci.yml)); a static build of the Chinese UI ([`web.yml`](.github/workflows/web.yml)); and integrity checks for the documentation's repository-internal links and image references ([`docs.yml`](.github/workflows/docs.yml)), catching regressions introduced during localization before they merge. Integration tests that require a database are verified alongside a PostgreSQL service isolated per package. The documentation link check runs as a deterministic script ([`scripts/check-doc-links.py`](scripts/check-doc-links.py)) that does not depend on an external network, so the many relative links the multilingual documents point at one another — and the screen-preview images — cannot merge while broken. Documentation anchor (`#heading`) links are also checked against headings using the same slug rules as GitHub, catching table-of-contents and cross-reference links that silently break when heading text changes. The detection-rule suite is handled by the merge gate described in the "Defense and detection resources" section above.
- **Periodically checks external-link liveness.** External links the documents point at — the defense guide's incident-reporting channels and standards references — depend on remote server state and are flaky, so they are kept out of the merge gate; instead a non-blocking workflow ([`external-links`](.github/workflows/external-links.yml)) runs a browser-User-Agent, GET, redirect-following check ([`scripts/check-external-links.py`](scripts/check-external-links.py)) every Monday and on manual dispatch. A host that is alive but blocks the check method (bot protection, rate limiting) and upstream-inherited dead links we cannot fix (an allowlist) are not counted as failures, so it turns red only when an external link our documents curate newly breaks.
- **Established contribution and governance infrastructure.** Added bug, feature, and translation issue templates ([`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/)) and a pull-request template ([`PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md)), a security-vulnerability reporting policy ([`SECURITY.en.md`](SECURITY.en.md)), and a code of conduct ([`CODE_OF_CONDUCT.en.md`](CODE_OF_CONDUCT.en.md)), so that external contributors submit issues, PRs, and security reports in a consistent format.
- **Completed an English documentation layer for overseas contributors.** This repository is Chinese-first, but English versions of the core documents are provided so that contributors, security researchers, and defenders who do not read Chinese can reach the same information. In addition to the English `README.en.md` and the defense guide ([`docs/defense-en.md`](docs/defense-en.md)), there are English versions of the changelog ([`CHANGELOG.en.md`](CHANGELOG.en.md)), the security reporting policy ([`SECURITY.en.md`](SECURITY.en.md)), the code of conduct ([`CODE_OF_CONDUCT.en.md`](CODE_OF_CONDUCT.en.md)), the contributing guide ([`CONTRIBUTING.en.md`](CONTRIBUTING.en.md)), the maintainer runbook ([`MAINTAINING.en.md`](MAINTAINING.en.md)), the traffic-evidence design document ([`docs/finding-traffic-evidence-en.md`](docs/finding-traffic-evidence-en.md)), and the bug, feature, and translation issue templates. The Chinese and English versions link to each other in their headers, so you can move to the other language from whichever one you arrive at. (The pull-request template is currently Chinese-only.)
- **Notes that the upstream repository is unreachable.** Upstream `Autumn-27/ARTEX`, its online demo and the `norma` SDK are all currently unreachable (checked 2026-10), and the README (zh/en), CONTRIBUTING, MAINTAINING, SECURITY and the defense guide carry that annotation so readers do not mistake a dead link for a problem with this repository.
